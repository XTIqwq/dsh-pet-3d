# 悬浮菜单与配饰穿脱（宠物身上的那张卡片）

> 2026-10-19。宠物正中间多了一只小熊 🐻：点它弹出**悬浮菜单**，里面能换整套外观、
> 逐件穿脱配饰。它和「设置 → 3D 桌宠」是**两件事**：设置页是配置，这张卡片是随手操作。
>
> 这份文档写给接手的人：数据格式、状态存在哪、渲染器语义、怎么验收、下一步往哪扩。

---

## 1. 交互（用户看到的样子）

| 动作 | 结果 |
|---|---|
| 鼠标**进入宠物方框** | 正中间浮现小熊 🐻（平时完全透明，且 `pointer-events: none`，不吃点击） |
| 点小熊 | 菜单在宠物**左侧**弹出（左边放不下就翻到右侧），不压在宠物身上 |
| 再点一次小熊 / 点 ✕ / 按 `Esc` | 收起菜单 |
| 拖动宠物 | 菜单跟着走（锚点是每次渲染按当前偏移重算的） |
| 点「整套外观」里的一套 | 等于换模型（走宿主 `POST /api/pet3d/set-pet`，就地热换） |
| 点某件配饰的开关 | 那件立刻穿上/脱下（渲染器按节点名隐藏，**不重建模型**） |
| 点「全部穿上 / 全部脱下」 | 一次性处理所有配饰（只碰配饰表里声明过的节点） |
| 开发者模式 + 点宠物 | 打开**检查面板**（动作/相位/视角/编排）—— 它在菜单**之外** |

**为什么小熊在正中心**：宠物是个 `size` 像素的透明方框（现在 500px），模型只占中间一块。
放在中心，一定落在躯干上；放在角落会有一半概率点到透明区，让人怀疑"没点中"。

**为什么"进入方框才浮现"**：宠物肚子上不该常驻一颗图标。判据用 **window 上的 pointermove +
矩形包含**，不是 `onPointerEnter/Leave` —— 小熊自己盖在方框中心，指针移到它身上时方框会收到
`pointerleave`，用 enter/leave 会把按钮在"要点的瞬间"藏掉。菜单开着时强制显示（否则指针挪到
卡片上入口就消失）。

**小熊是独立元素**，不在舞台方框里 —— 所以点它不会触发"按住拖动"或检查面板，两套交互不打架。

> **界面边界（用户明确要求）**：这张卡片是给用户的互动面板，**不承载开发者 UI**。
> 「动作面板」只能由"开发者模式 + 点宠物"打开，不要加回菜单里。

## 2. 数据：`appearance.json`（每个模型目录一份，可选）

放在模型目录（和 `choreography.json`、`options.json` 同级），由既有的
`/pet3d/<id>/<相对路径>` 资源路由原样投递。**改文件 ≤2 秒生效，不用刷新页面、不用重启应用。**

```jsonc
{
  "version": 1,
  "title": "夏日装",                       // 可选：菜单标题 +「整套外观」里的标签
  "pieces": [
    { "id": "hat", "label": "草帽", "nodes": ["PanYinhu_ModHat"] },
    { "id": "goggles", "label": "潜水镜", "nodes": ["body_top1"] },
    { "id": "tag", "label": "木牌", "nodes": ["PanYinhu_ModAcc"], "defaultHidden": true }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `title` | 这套外观叫什么。缺省退回模型 id。**「整套外观」那一排的标签就是它** |
| `pieces[].id` | 稳定 id（本地存储与守卫按它定位）。改名 = 换一件新配饰 |
| `pieces[].label` | 菜单上显示的名字 |
| `pieces[].nodes` | 这件配饰占哪些 **glTF 节点名**（不是网格名！这份资产网格名是空的，名字在节点上） |
| `pieces[].defaultHidden` | 默认就是脱下的；不写 = 默认穿在身上 |

### 三条纪律（守卫会强制检查）

1. **不许把身体和脸写进 pieces**。`body_low0` 是全身、`PanYinhu_Face` 是脸 ——
   写进去等于给用户一个"让宠物消失"的开关。`tools/check-appearance.mjs` 按
   "顶点最多的网格 = 主体" 判定，也会拦下任何单件占 >60% 顶点的条目。
2. **只写网格节点，不写组节点**（`ModBodyGroups` 这种会连组里所有东西一起藏）。
3. 一个节点只能属于一件配饰（重复声明按先出现的算，并报问题）。

## 3. 状态存在哪（以及为什么没放宿主）

**客户端 `localStorage`**，键 `pet3d:appearance:<模型id>`，值是"脱下来的节点名数组"。

- 为什么不在 `options.json`：那份文件被 `OPTION_FIELDS` 锁死在 5 个字段（守卫检查 `≤5`），
  而且它是**模型作者**的配置，不是**用户**的选择。
- 为什么没走宿主 `pet3d.json`：宿主侧改动（`persist.ts`/`service.ts`/`routes.ts`）需要
  **真退出应用重开**才生效，而这轮只想让用户刷新一下页面就能用。将来若要与远端设备同步，
  再把它迁到宿主（形状照抄 `display`）即可，客户端的接口不用改。

每换一个模型就读那个模型自己的一份 —— 换模型不该把另一套的配饰也脱了。

## 4. 渲染器语义（`setHiddenNodes`）

```ts
handle.setHiddenNodes(['PanYinhu_ModHat', 'body_acc2'])   // 传的是"要藏起来的节点"
```

| 语义 | 为什么 |
|---|---|
| 传**整张表**，不是单条增删 | 幂等：热换、刷新、重复调用都得到同一个画面 |
| 描边壳 `<网格>__outline` 连带隐藏 | 只藏网格会在 `shell` 模式下剩一圈黑边 |
| 状态记在**句柄**上，热换后自动重放 | 换模型/重导入会换掉整棵场景图，新节点默认全可见 |
| **不动相机** | 相机在装载时按整个模型拟合；藏一件配饰不该让镜头突然推近 |
| 恢复只动"我们藏过的" | 模型自己设的不可见节点不会被点亮 |

面板仪表现在多了三个字段，都是"点开关真的作用到 GPU 上了"的证据：

| 字段 | 含义 |
|---|---|
| `parts=` | `all` = 一件没脱；否则列出被藏起来的节点名 |
| `dc=` | 本帧绘制调用数（脱掉草帽：16 → 14） |
| `tri=` | 本帧三角形数（59119 → 56761） |

> 为什么强调这两个数：截图会被动画噪声干扰（宠物一直在动），"画面好像变了"很难判定；
> 而**绘制调用数下降**是"GPU 真的没画它"的硬证据。

## 5. 验收

### 离线（改完数据先跑）

```powershell
node tools/check-appearance.mjs                    # 两个模型逐件核对节点名/组节点/身体护栏
node tools/check-appearance.mjs --json             # 机器可读
```

### 真窗口（"用户看到的是不是对的"的唯一权威）

```powershell
node tools/verify-pet-menu.mjs --wait 25           # 悬停浮现/贴边/数据驱动/穿脱/持久化/换模型/互动/Esc/开发者 UI 不在菜单里
```

它断言的重点（都是能失败的那种）：

- 指针在方框外时小熊是藏的、且不吃点击；挪进方框才浮现；
- 小熊中心 = 舞台中心（±2px）；菜单不压在宠物方框上、整个在视口内；
- 配饰行数与 `appearance.json` 一致、每行名字来自文件；
- 脱一件：`data-pet3d-hidden` 变、开关状态变、`parts=` 变、**`dc`/`tri` 下降**；
- 刷新页面后仍然是脱着的（本地持久化）且渲染器重放了状态；
- 全部脱下：每个声明过的节点都藏了，绘制调用掉到 6；
- 换模型：宿主选中变化、菜单不关、配饰表跟着换；
- 菜单里**没有**开发者入口；点宠物（开发者模式）仍然打开检查面板；
- 收尾：模型与配饰全部复原、页面无未捕获异常。

截图落在 `_probe/menu/`（`menu-open.png`、`menu-piece-off.png`、`menu-all-off.png`）。

## 6. 互动（v1.0.0 已实现）

「互动」页签是**数据驱动**的：模型目录里的 `interactions.json` 决定按钮、动作、台词和好感度上限。

```jsonc
{
  "version": 1,
  "actions": [
    { "id": "pat", "label": "摸摸", "clip": "Avatar_..._Galgame_Shy_Loop", "line": "唔…舒服。", "affinity": 1 }
  ],
  "affinity": { "max": 10, "lines": ["……", "今天心情不错。", "最喜欢你了。"] }
}
```

实现落点（都在 `PetStage` 的受控状态里）：

- 按钮 → `handle.playNamed(clip, false)`：**单条试播**，放完自己回到当前相位的循环段；
- 播不了（动作名写错 / 数据没就绪）就明说，**不装作成功**，也不加好感度；
- 台词气泡 3 秒后消失；好感度存 `localStorage`（键 `pet3d:affinity:<模型 id>`，换模型各记一份）；
- 同一个按钮 2 秒冷却，防止动作还没收招就叠第二条；
- 好感度满值时换成 `affinity.lines` 最后一句；
- 没有 `interactions.json` 时整个页签显示「这个模型还没配互动」，不报错、不空白、不放空按钮。

动作名必须是 `clips.json` 里真实存在的名字 —— 守卫会逐条核对，写错会被抓出来。

## 7. 已知边界

- 菜单**不会点外面自动关**：宠物是"按住拖"的，加一层全屏遮罩会把拖动吃掉。用 ✕ / 小熊 / Esc 关。
- 小熊盖住宠物正中间 30px：想从肚子那里开始拖动会变成点菜单（拖别处即可）。
- 当前唯一模型 `panyinhu` 只有 1 件配饰（帽子）、没有款式组；多款互斥组的能力还在代码里，
  需要模型目录带 `appearance.json` 的 `groups` 才会出现（夏日装已删除，配置留档可恢复）。
- 配饰是**按节点整件**隐藏，不支持"半脱"（比如把帽子只摘一半）。

# 已知问题

本文记录 `dsh-pet-3d` 当前版本（v1.0.3）**尚未修复**的缺陷。

> 复核时间：2026-10-20
> 复核基准：`packages/dsh-pet-3d/src/` 当前源码（行号以此为准）

| # | 级别 | 问题 | 状态 |
|---|---|---|---|
| 1 | **P0** | 自动重导入对「导入失败」永不 backoff，每 5 秒起一个导入器子进程 | 未修 |
| 2 | **P1** | ZIP / 复制分发的模型解压后 `stale` 恒为 true（mtime 容差 2 ms） | 未修 |
| 3 | **P2** | `import.json.importerScript` 为空串时，「导入器不符」闸门失效 | 未修 |

问题 1、2、3 属于**同一条根因链**，建议一起看。

## P0：导入失败时不 backoff，每 5 秒起一个导入器子进程

### 现象

`SWEEP_MIN_INTERVAL_MS = 5e3`，扫描每 5 秒跑一轮。当某个模型的源文件被判为「有改动」时，
每一轮都会 `spawn` 一个 Node 子进程去跑导入器。

实测（32 秒 / 约 6 个扫描周期）：

```
导入器被调用次数: 6
importStall: (空 —— 永不放弃)
stale: true
```

在真实机器上，176 MB 的模型每次重导都要读一遍 FBX / 重写 `clips.bin`，
子进程因各种原因失败后立刻退出，下一轮再来。

### 位置

`packages/dsh-pet-3d/src/importer.ts`，`run()` 第 575–593 行：

```ts
const started = runImporter(modelDir, this.config).then((outcome) => {
  this.inflight.delete(modelDir)
  this.lastOutcome.set(modelDir, outcome)
  if (outcome.ok) {                                   // ← 只有成功才处理
    if (outcome.revision !== before) {
      this.autoStalled.delete(modelDir)
    } else if (opts.auto === true) {
      this.autoStalled.set(modelDir, `自动重导入已停止：…`)
    }
    this.onChanged(modelDir)
  }
  return outcome                                      // ← 失败时什么都没记
})
```

`sweep()` 第 637–658 行：

```ts
if (staleSources(dir, readImportMeta(dir)).length === 0) continue
started.push(dir)
void this.run(dir, { auto: true }).catch(() => {})    // ← 失败也照跑，下轮再来
```

失败路径既不写 `autoStalled`，也不退避 → **无限循环**。

### 影响

- 每个扫描周期一个子进程，CPU / IO 持续占用
- 大模型（150 MB `clips.bin`）每次重导都要重写磁盘
- 面板上的 `importStall` 始终为空，用户看不出「它一直在失败」

### 建议修复

1. **最小改动**：`outcome.ok === false` 时同样写 `autoStalled.set(...)`，理由带错误摘要
2. **更好**：指数退避（5s → 30s → 5min），并提供「手动重载清零」的入口
3. 无论哪种，`/api/pet3d/state` 的 `importStall` 在失败时也要返回

## P1：复制 / ZIP 分发的模型解压后即 stale

### 现象

全新解压、**未做任何改动**，6 张贴图的 mtime 与 `import.json.sources` 记录全部对不上：

```
PanYinhu_Body_Map1_D.png   delta = -74 ms
PanYinhu_Body_Map1_N.png   delta = -77 ms
PanYinhu_Body_Map2_D.png   delta = -79 ms
PanYinhu_Body_Map2_N.png   delta = -80 ms
PanYinhu_Face_D.png        delta = -81 ms
PanYinhu_Face_N.png        delta = -83 ms
```

（直接解压 ZIP 时差值可达 -1074 ~ -1083 ms，取决于打包方式；两种都远超容差。）

### 位置

`packages/dsh-pet-3d/src/importer.ts`：

```ts
// 第 161 行
/** Two mtimes name the same source unless they differ by more than this, ms. */
export const MTIME_TOLERANCE_MS = 2

// 第 278 行
} else if (Math.abs(current.mtimeMs - stamp.mtimeMs) > MTIME_TOLERANCE_MS) {
  rows.push({ key, status: 'mtime', ... })
```

`import.json.sources` 记录的是**打包者机器**上的 mtime：

- ZIP 只存 2 秒精度的 DOS 时间戳，解压必然对不上
- 即便精度够，打包者的文件时间也不会等于接收方的
- 普通文件复制也会改变 mtime（实测差 74~83 ms）

**结论：任何经过复制或 ZIP 分发的模型目录，`stale` 必然为 true。**
这不是用户操作问题。

### 影响

直接触发 P0：模型一旦装进来就永远处于「有改动」状态。

### 建议修复

1. **打包时清空 `sources`**（或写 `sources: {}`），让已有闸门生效 ——
   源码注释已写明设计意图：
   > `if (meta.sources === undefined) return { ok: false, reason: 'import.json 没有 sources 记录（不是本协议导入的，跳过自动重导入）' }`
2. 或把 mtime 容差放宽到秒级，并**优先比 `sha256`**（`sources` 里已记了 `sha256`，只是没被用来判 stale）

### 临时绕过

编辑模型的 `.import/import.json`，把 `sources` 改成 `{}`。模型照常显示，
自动重导入会被闸门跳过。

## P2：`importerScript` 为空串时闸门失效

### 现象

`autoEligible()` 的三道闸门里，第三道依赖 `import.json.importerScript`：

```ts
// 第 620–623 行
if (typeof meta.importerScript === 'string' && meta.importerScript !== ''
  && !samePath(meta.importerScript, this.config.script)) {
  return { ok: false, reason: `import.json 记录的导入器是 ${meta.importerScript}，与当前配置不符` }
}
```

1.0.1 的 `import.json` 里该字段是 `"tools/pet3d-import.mjs"`（相对路径），
`samePath()` 用 `resolve()` 后比较，永不相等 → **整个自动重导入被永久跳过**
（意外挡住了 P0）。

1.0.2 / 1.0.3 把该字段清空为 `""` → 闸门直接放行 → **P0 暴露**。

### 影响

从「永远不跑」变成「每 5 秒跑一次」。同时 `importConflict()` 对第三方产物也失去保护。

### 建议修复

不要清空字段，改为写**绝对路径**，或写成可比较的结构
（如 `{ "name": "pet3d-import.mjs", "version": 5 }`），让 `samePath()` / `basename()`
两条判据都能工作。

## 复现步骤（P0 + P1 最小化）

```powershell
# 1. 准备一个模型目录（复制或解压得到）
$m = "$env:DSH_HOME\models\<id>"

# 2. 确认 stale 恒为 true
$j = Get-Content "$m\.import\import.json" -Raw | ConvertFrom-Json
foreach ($k in $j.sources.PSObject.Properties.Name) {
  $f = Join-Path $m ($k -replace '/','\')
  $d = [math]::Round(([datetimeoffset](Get-Item $f).LastWriteTimeUtc).ToUnixTimeMilliseconds()) - $j.sources.$k.mtimeMs
  "{0,-40} delta={1}ms" -f (Split-Path $k -Leaf), $d     # 全部 |delta| > 2
}

# 3. 启动 DSH，观察：每 5 秒出现一次导入器子进程
#    且 /api/pet3d/state 的 importStall 始终为空
```

## 其他已知限制（非缺陷）

- **模型不进包**：动作资产动辄数百 MB，只能随模型目录分发
- **特效 clip 多为空壳**：部分带特效轨道的 clip 是 0 轨道占位，播放时「有名字但画面不动」
- **模型 UV 口径随来源而变**：不同来源导出的 V 轴约定不一致，导入时需按实际情况选择是否翻转
